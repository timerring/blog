1. Differences Between Error and Exception #

An Error is a failure that a program cannot handle, such as OutOfMemoryError or ThreadDeath. When these occur, the Java Virtual Machine (JVM) generally terminates the thread. Such failures are fatal to the program and cannot be caught and handled.

An Exception is an exceptional condition that the program itself can handle. Exceptions fall into two categories: runtime and non-runtime exceptions. Programs should handle these exceptions whenever possible.

3. Differences Between Runtime and Non-Runtime Exceptions #

Runtime exceptions are RuntimeException and its subclasses, such as NullPointerException and IndexOutOfBoundsException. These are unchecked exceptions: a program may catch and handle them or leave them unhandled. They generally arise from errors in program logic, so the program should avoid them through its logic whenever possible.

Non-runtime exceptions are exceptions other than RuntimeException; they belong to Exception and its subclasses. The language requires them to be handled, or the program will not compile. IOException, SQLException, and user-defined Exception subclasses are checked exceptions. Generally, avoid defining custom checked exceptions. (All checked exceptions must be explicitly handled by catching or throwing them.)

5. Built-in Exception Methods #

Exceptions have many APIs.

MethodDescription
public String getMessage()Returns details about the exception. This message is initialized in the Throwable constructor.
public Throwable getCause()Returns a Throwable representing the cause of the exception.
public String toString()Returns a brief description of this Throwable.
public void printStackTrace()Prints this Throwable and its backtrace to the standard error stream (in stack order).
public StackTraceElement [] getStackTrace()Returns an array of stack frames. Element 0 is the top of the stack; the last element is the bottom of the method call stack.
public Throwable fillInStackTrace()Fills in the Throwable’s stack trace with the current call stack, adding to any prior stack information.

6. Catching Exceptions #

import java.util.Scanner;  
  
public class Main {  
  
    private static void foo() {  
        int[] array = new int[5];  
        for (int i = 0; i < 5; i ++ )  
            array[i] = i;  
  
        Scanner sc = new Scanner(System.in);  
        int k = sc.nextInt();  
        int x = sc.nextInt();  
  
        try {  
            array[k] /= x;  
        } catch (ArithmeticException e) {  
            System.out.println("除零错误！");  
            // The API prints error details: / by zero            System.out.println(e.getMessage());  
            // The API prints the error stack trace  
            // Note: printing after catching does not terminate the program. Without a catch, the error is printed similarly, but the program terminates.  
            e.printStackTrace();  
        } catch (ArrayIndexOutOfBoundsException e) {  
            System.out.println("数组越界！");  
            e.printStackTrace();  
            // Code that runs whether or not an exception is caught can go in finally  
            // Even if catch contains return, finally runs before returning (statements after finally then do not run).  
        } finally {  
            for (int i = 0; i < 5; i ++ ) {  
                System.out.println(array[i]);  
            }  
        }  
//        System.out.println("程序执行完毕！");  
    }  
  
    public static void main(String[] args) {  
        foo();  
    }  
}

7. Throwing Exceptions #

throw: Throws an exception inside a function.
throws: Declares possible exceptions in a function definition.

Checked exceptions must be caught or thrown. Exception handling can be nested: put a try/catch inside a try or catch block.

import java.io.IOException;  
import java.util.Scanner;  
  
public class Main {  
  
    // Declare multiple exceptions with throws  
    private static void foo() throws IOException, NoSuchFieldException {  
        Scanner sc = new Scanner(System.in);  
        int x = sc.nextInt();  
        if (x == 1)  
            throw new IOException("找不到文件！！！");  
        else            throw new NoSuchFieldException("自定义异常");  
    }  
  
    public static void main(String[] args) {  
        try {  
            // We throw an exception ourselves  
            foo();  
        } catch (IOException e) {  
            // Then we catch that exception ourselves  
            // Alternatively, main could throw it to the virtual machine  
            System.out.println("IOException!");  
            e.printStackTrace();  
        } catch (NoSuchFieldException e) {  
            System.out.println("NoSuchFieldException!");  
            e.printStackTrace();  
        }  
    }  
}

8. try-with-resources #

Since JDK 7, Java has provided try-with-resources syntax to open resources and ensure that each is closed automatically after the statement completes.

try declares and instantiates resources; catch handles any exceptions that may arise when closing them.

import java.io.*;  
  
public class Main {  
  
    public static void main(String[] args) {  
        String line;  
        try (  
                BufferedReader br = new BufferedReader(new FileReader("input.txt"));  
                BufferedWriter bw = new BufferedWriter(new FileWriter("output.txt"));  
        ) {  
            while ((line = br.readLine()) != null) {  
                System.out.println("Line => " + line);  
                bw.write("copy: " + line + "\n");  
            }  
            bw.flush();  
        } catch (IOException e) {  
            System.out.println("IOException in try block =>" + e.getMessage());  
        }  
    }  
}
